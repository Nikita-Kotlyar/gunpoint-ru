# Gunpoint RU — техническое описание патча

> Документ описывает **что именно** меняет патчер, **по каким адресам/смещениям**
> и **почему** это сделано так. Версия игры: Steam **Gunpoint 1.82** (AppID 206190).
> Патчер: `05_Patcher` (Rust, нативный exe, без внешних зависимостей).

- другой версии игры (GOG, старая/новая сборка);

- повреждённой установки.

блокируется и предлагается восстановление.

## 1. Что меняется в `Gunpoint.exe`

### 1.1. Общая схема

`Gunpoint.exe` — PE32 (i386), image base `0x400000`, 4 секции в оригинале:
`.text`, `.rdata`, `.data`, `.rsrc`.

Патч делает три вещи:

1. Добавляет пятую секцию **`.gtxt`** с пулом переведённых wide-строк.
2. Перецеливает все `push imm32`, которые указывали на старые wide-строки,
   на новые адреса в `.gtxt`.
3. Меняет один байт в конвертере `std::string → std::wstring`
   (`MOVSX → MOVZX`), чтобы CP1251-байты в `.gpc` превращались в нужные
   code points.

Оригинальный `.text` не переписывается: все изменения — это точечные
записи в заголовок PE, в 4-байтовые операнды `push` и один байт в `.text`.
Приложенный блок `.gtxt` добавляется в конец файла.

### 1.2. Секция `.gtxt`

| Параметр | Значение |
|---|---|
| Имя | `.gtxt` |
| RVA | `0x443000` |
| Raw offset | `0x408A00` (= размер оригинального exe) |
| VirtualSize | `0x17122` |
| SizeOfRawData | `0x17200` |
| Characteristics | `0x40000040` (readable, initialized data) |
| NumberOfSections | 4 → 5 |
| SizeOfImage | `0x45B000` |

Пулы строк:

- строки хранятся как **UTF-16LE**, каждая завершена `00 00`;
- каждая строка выровнена на 4 байта;
- переводы предварительно проходят **glyph remap** (см. §1.3).

В патче 784 записи (`push`-ссылки), 638 уникальных текстов. Размер
приложенного блока — **94 720 байт**. Изменённых диапазонов в оригинальной
части exe — **797**, суммарно **2 351 байт** (заголовок PE, 784 операнда
`push`, байт `MOVZX`).

### 1.3. Glyph remap: почему не настоящий Unicode

Движок принимает только code points `≤ 0x2BB`. Проверка находится в
`HasChar` (`0x42D120`):

```asm
cmp eax, 0x2BB
ja  .not_found
cmp dword ptr [ecx+eax*4+0xFB0], -1
je  .not_found
```

Таблица символов фиксирована: 700 записей по адресу `+0xFB0`. Настоящие
кириллические `U+0410+` туда не проходят — движок нарисует `%`.

Поэтому кириллица кодируется кодами CP1251, которые уже есть в `.fnt`:

| Буквы | Код |
|---|---|
| А–Я | `U+00C0–U+00DF` |
| а–я | `U+00E0–U+00FF` |
| Ё / ё | `U+00A8` / `U+00B8` |

Для wide-строк exe это UTF-16 code units; для `.gpc` — однобайтовые
CP1251-байты. Соответствие «CP1251-байт → code point» совпадает численно.

### 1.4. Перецеливание `push imm32`

В `.rdata` wide-строки адресуются через `push imm32` (например,
`push 0x71D390`). Скрипт `exe_patch.py`:

1. Для каждой переведённой строки находит все 4-байтовые вхождения старого
   адреса в `.text` и `.data`.
2. Патчит только реальные `push imm32` (предыдущий байт `0x68`).
3. Ложные совпадения внутри чужих инструкций пропускает. Примеры:
   `PSYCHOPATH` (`0x72E8C8`) и `BRUTAL` (`0x72E8E0`) — байтовые
   совпадения при предыдущем байте `0x33`/`0x4D`, их трогать нельзя.
4. Проверяет, что реальных ссылок на старые адреса не осталось.

В `.data` ссылок у переведённых строк нет (проверено отдельно).

### 1.5. `MOVSX → MOVZX`: почему в чате были `%`

Телефонные диалоги читаются из `.gpc` так:

```
gml::ReadInScriptFile            0x51EAC0
  → file_text_read_string        0x583550
    → FileManager::ReadString    0x4280B0   (возвращает std::string, сырые байты)
    → std::wstring::_Construct   0x41E600   (сборка wide-строки)
```

В `0x41E675` стоит:

```asm
66 0f be 10   movsbw (%eax),%dx   ; MOVSX — расширение СО ЗНАКОМ
```

Байт `0xC0` (CP1251 «А») расширяется как `0xFFC0`, а не `0x00C0`.
`HasChar` отбрасывает всё `> 0x2BB` → глиф не найден → `%`.

Поэтому и UTF-8, и CP1251 давали `%`: важны не байты файла, а знаковое
расширение при сборке wide-строки. UTF-8 давал два байта на букву
(`0xC3 0x80` → `U+FFC3 U+FF80`), CP1251 — один (`0xCA` → `U+FFCA`).

Исправление — один байт:

| | |
|---|---|
| VA | `0x41E677` |
| Файловое смещение | `0x1DA77` (`.text` raw `0x400`, RVA `0x1000`) |
| Было | `66 0F BE 10` |
| Стало | `66 0F B6 10` |

После патча байты `0x80–0xFF` дают `U+0080–U+00FF`, то есть CP1251-байты
`0xC0–0xFF` попадают ровно в пропатченные слоты глифов. Для ASCII
(`0x00–0x7F`) поведение не меняется.

Побочный эффект: этот же шаблон `0x41E600` используется в трёх функциях
Steam Workshop для узких строк. Для байтов ≥ `0x80` они и раньше получали
мусор `U+FFxx`; теперь — `U+00xx`. Для ASCII ничего не меняется.

## 2. Что меняется в `Gunpoint.wad`

### 2.1. Формат WAD

```c
u32 base_offset;   // 0x1B74
u32 file_count;    // 162
for each entry:
    u32 name_len;
    char name[name_len];   // без нуля, ASCII
    u32 size;
    u32 offset;            // абсолютный = offset + base_offset
```

- данные **не сжаты**;
- 162 записи: 85 `Sounds\`, 65 `GL\`, 12 `Fonts\`;
- длина таблицы заголовка: `8 + Σ(4 + name_len + 8) = 7028 = 0x1B74`,
  поэтому `base_offset` остаётся прежним;
- после патча размер WAD: `456 398 543 → 456 380 021` байт.

### 2.2. Заменяемые записи (25)

| Группа | Кол-во | Что меняется |
|---|---:|---|
| `Fonts/*.fnt` | 12 | BMFont XML: добавляются 66 кириллических глифов, координаты/`xadvance` |
| `GL/Fonts/*_0.png.phyre` | 12 | L8-атлас: в свободные места/новую упаковку вписываются глифы |
| `GL/gunpoint_fonts.bin` | 1 | у всех 12 шрифтов `last = 0xFF` |

Патчер **не пересобирает WAD с нуля из чужих файлов** и не качает
456 МБ. Он читает WAD пользователя, заменяет только эти 25 записей,
пересчитывает offsets и пишет новый WAD локально.

### 2.3. Формат шрифтов

- `.fnt` — XML BMFont: `<char id="..." x="..." y="..." width="..." height="..." xoffset="..." yoffset="..." xadvance="..." />`.
- Атлас `.phyre` — сырой **L8**; последние `W*H` байт файла — пиксели.
- Данные в атласе хранятся **bottom-up**. Для глифа с top-based `y` из `.fnt`
  строка `r` (0 = верх глифа) лежит по индексу `H - y - 1 - r`.
- `font_patch.py` (11 шрифтов) пишет `dst = raw_y + (h - 1 - r)`,
  а в `.fnt` ставит `fnt_y = H - raw_y - h`.
- `font_repack_fgeorgia.py` делает полную перепаковку fGeorgia.

### 2.4. fGeorgia

fGeorgia (48 px, 512×512) не влезал в свободное место, поэтому
перепакован полностью:

- оставлены ASCII (32–126) и Latin-1 (160–255);
- удалены неиспользуемые Latin Extended (`0x100–0x2BB`);
- 66 слотов заменены полноразмерной кириллицей;
- итог: 191 символ, `.fnt` 22 859 байт (оригинал — 316 символов,
  37 921 байт).

Критичный момент — ориентация. В первой версии скрипт читал строки как
`H - y - h + r` (снизу вверх), а писал top-down. Из-за этого все
**скопированные** латинские буквы и цифры оказывались перевёрнуты по
вертикали (HUD показывал зеркальные цифры). Правильно:

```python
rows = [px[(H - ch['y'] - 1 - r) * W + ch['x'] : ...] for r in range(ch['h'])]
```

Кириллица не страдала: она рисуется GDI и пишется сразу в правильном порядке.

### 2.5. `gunpoint_fonts.bin`

- 584 байта: `u32 count=12`, 12 × `u32` индексов, затем 12 записей по 44 байта.
- Поля записи: `[0]` — служебное, `[1]` — id, `[2..5]` — имя (16 байт),
  `[6]` — ?, `[7]` — size, `[8]` — first, `[9]` — last, `[10]` — flags.
- Патч ставит `last = 0xFF` для всех 12 шрифтов (`off=0x38` — начало id,
  `off+32` — last). Исходно было `first=32, last=127`.

### 2.6. Почему патчер не хранит полные атласы

В патчере лежат:

- полные `.fnt` (наша изменённая XML-метаинформация, ~443 КБ);
- **range diff** для `.phyre` (только изменённые прямоугольники глифов,
  ~314 КБ, включая fGeorgia);
- diff `gunpoint_fonts.bin` (12 байт);
- `.gtxt`-пул переводов (94 720 байт);
- 44 `.gpc` (46 416 байт).

Полные игровые атласы не встраиваются: патчер применяет диапазоны к
атласам пользователя. Это и меньше по размеру, и аккуратнее с точки
зрения распространения игровых ассетов.

## 3. Что меняется в `Scripts/*.gpc`

- 44 файла, plain text, CRLF.
- 915 непустых текстовых строк; блоки `Them:` / `Me:` / `After:` / `END SCENE`.
- Числа — **1-based номера строк для переходов**, не тайминги.
- Нельзя менять: количество строк, позиции пустых строк, числа,
  токены `Them:`, `Me:`, `After:`, `END SCENE`.
- Кодировка патча — **CP1251 без BOM** (после MOVZX-патча это ровно те
  code points, которые нужны шрифтам).
- UTF-8 для `.gpc` не использовать: два байта на букву не пройдут
  через `MOVSX/MOVZX`-путь так, как нужно.

Патчер пишет 44 файла в `Scripts\`, предварительно сохранив оригиналы
в резервную копию.

## 4. Как работает патчер

### 4.1. Поиск игры

1. Реестр:
   - `HKCU\Software\Valve\Steam` → `SteamPath`
   - `HKLM\SOFTWARE\WOW6432Node\Valve\Steam` → `InstallPath`
2. `steamapps\libraryfolders.vdf` — все библиотеки Steam.
3. `steamapps\appmanifest_206190.acf` → `installdir`.
4. Кандидаты: `<library>\steamapps\common\Gunpoint`.
5. Если ничего не найдено или найдено несколько — ручной выбор папки
   через нативный диалог Windows.

### 4.2. Проверка и бэкап

- Хэши `Gunpoint.exe` и `Gunpoint.wad` сверяются с §0.
- Создаётся `%LOCALAPPDATA%\GunpointRU\backup\backup-<unix-time>\`:
  - `Gunpoint.exe`
  - `Gunpoint.wad`
  - `Scripts\*.gpc` (44 оригинала)
  - `backup_info.txt` (путь к игре, версия патчера)
- Для WAD нужно ~456 МБ; в процессе пересборки — ещё ~456 МБ
  временно. Свободное место: желательно ≥ 1.5 ГБ.

### 4.3. Применение

1. **exe**: читается оригинал, применяются 797 точечных записей,
   добавляется `.gtxt` (94 720 байт), проверяется SHA-256 результата.
2. **WAD**: читается заголовок (162 записи), проверяются размеры 25
   записей, собирается новый заголовок с пересчитанными offsets,
   payload пишется потоково. Для 13 записей применяются range diff,
   для 12 `.fnt` — полная замена. Проверяется SHA-256 результата.
3. **gpc**: 44 файла пишутся в CP1251, каждый проверяется по SHA-256.

Все замены — через временный файл в той же папке и
`MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`.
Это не оставляет полузаписанных файлов при сбое.

### 4.4. Восстановление

`--restore` берёт последнюю резервную копию для этой папки игры и
возвращает `Gunpoint.exe`, `Gunpoint.wad` и 44 `.gpc`. После restore
хэши снова равны оригиналам из §0.

### 4.5. Если Steam откатил файлы

Steam → Свойства игры → «Проверить целостность файлов» вернёт
оригинальные `Gunpoint.exe`/`Gunpoint.wad`. После этого патчер можно
запустить снова. Резервная копия в `%LOCALAPPDATA%` при этом не
удаляется.

## 5. Почему патчер не должен пугать антивирус

- Нативный Rust-бинарник, **без PyInstaller/Nuitka/UPX**, без упаковщиков.
- **Нет сетевого кода**, нет загрузки файлов, нет автозапуска,
  нет инжекции в процессы, нет изменения реестра (только чтение).
- Статическая линковка CRT; импортируются только системные DLL:
  `ADVAPI32`, `KERNEL32`, `SHELL32`, `ole32`, `msvcrt`, `ntdll`.
- Все действия — локальная модификация файлов игры по явной команде
  пользователя, с бэкапом и проверкой хэшей.
- Размер exe ~1.29 МБ, внутри — только наши данные патча.

Тем не менее любой патчер, меняющий чужой `.exe`, может попадать под
эвристику «modifies executable». Поэтому:
- выкладывайте исходники и SHA-256;
- не используйте упаковщики;
- по возможности подпишите exe Authenticode-сертификатом;
- проверяйте на VirusTotal перед релизом.

## 7. Юридические замечания

- Патчер не содержит `Gunpoint.exe`, `Gunpoint.wad`, PDB, музыки,
  уровней или полных шрифтовых атласов. Он модифицирует **легально
  установленную** копию игры.
- Для работы нужна лицензионная Steam-версия Gunpoint 1.82.
- Перевод — производная работа от текста игры; распространяйте его
  бесплатно, с указанием автора и без продажи.
- PDB `Gunpoint.exe.pdb` — проприетарная отладочная база; не
  распространяйте её.
- Steam Workshop у Gunpoint предназначен только для уровней; не
  загружайте туда модифицированные exe/WAD.
- Рекомендуемая площадка: GitHub Releases + Steam Community Guide
  со ссылкой. Nexus Mods/ModDB — как зеркала.
